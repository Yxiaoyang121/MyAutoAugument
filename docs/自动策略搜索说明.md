# 自动策略搜索说明

## 当前评估方式

项目现在支持四种 evaluator：

- `proxy`：不训练模型，只用代理指标检查增强后图片、bbox、曝光、方差和策略多样性。速度快，适合预筛选，但不是真实 mAP。
- `command`：通用外部命令 evaluator，从 stdout/stderr 中用正则解析一个 score。
- `yolo`：使用已有模型权重做 YOLO val，从日志解析 `mAP50` 或 `mAP50-95`。它不重新训练，评估的是已有模型对增强数据的验证结果。
- `train_yolo`：每个 policy 都增强训练集，每个 trial 都训练一个小 YOLO 模型，再用固定验证集计算 mAP。这是当前项目真正的自动增强策略搜索闭环。

## train_yolo 完整闭环

`train_yolo` 的流程是：

1. SearchSpace 随机采样一个 policy。
2. 只对训练集 train 应用该 policy。
3. 生成当前 trial 的 YOLO 训练数据集。
4. 自动生成当前 trial 的 `data.yaml`。
5. 调用 YOLO train 命令训练一个小模型。
6. 从 train 输出目录中寻找 `best.pt`。
7. 复制 `best.pt` 到当前 trial 的 `weights/best.pt`。
8. 调用 YOLO val 命令，在固定 val 验证集上验证。
9. 从 val 日志解析 `mAP50` 或 `mAP50-95`。
10. 将 mAP 作为当前 policy 的 score。
11. 多个 trial 后输出 `best_policy.json`、`trials.csv`、`trials.json`。

验证集不会做增强，避免评估不客观。

## 数据集结构

标准 YOLO train/val 结构：

```text
dataset_root/
  images/
    train/
    val/
  labels/
    train/
    val/
```

简单结构也支持：

```text
dataset_root/
  images/
  labels/
```

简单结构在 `train_yolo` 模式下会按 `--val-ratio` 固定划分 train/val。也可以显式传：

```text
--train-images
--train-labels
--val-images
--val-labels
```

优先级：

1. 显式传入 train/val 路径。
2. 自动识别 `images/train` 和 `images/val`。
3. 简单 `images/labels` 按 `--val-ratio` 划分。

## 关键文件说明

- `README.txt`：说明本目录是什么、输入数据集在哪里、图片和标签在哪里、best policy 和 trials.csv 在哪里、evaluator 类型和 metric。
- `run_config.json`：保存本次运行参数、解析后的路径、train/val 划分方式。
- `input_dataset.txt`：策略搜索输入数据集路径记录。
- `source_dataset.txt`：应用 best policy 时的源数据集路径记录。
- `val_reference.txt`：记录当前 trial 使用的固定验证集路径，说明 val 未增强。
- `metrics.json`：当前 trial 的 mAP、hybrid 分数、命令、日志路径和 best.pt 路径。

## YOLO train 命令

默认 train 命令：

```bat
yolo detect train model={model} data={dataset_yaml} epochs={epochs} imgsz={imgsz} batch={batch} project={trial_dir}/train_runs name=train exist_ok=True
```

支持占位符：

- `{dataset_yaml}`
- `{trial_dir}`
- `{dataset_dir}`
- `{train_images_dir}`
- `{train_labels_dir}`
- `{val_images_dir}`
- `{val_labels_dir}`
- `{epochs}`
- `{imgsz}`
- `{batch}`
- `{model}`

自定义示例：

```bat
--train-command "yolo detect train model={model} data={dataset_yaml} epochs={epochs} imgsz={imgsz} batch={batch} project={trial_dir}/train_runs name=train exist_ok=True"
```

## YOLO val 命令

默认 val 命令：

```bat
yolo detect val model={best_pt} data={dataset_yaml}
```

支持占位符：

- `{best_pt}`
- `{dataset_yaml}`
- `{trial_dir}`
- `{dataset_dir}`
- `{val_images_dir}`
- `{val_labels_dir}`

训练结束后会优先查找：

```text
trial_dir/train_runs/train/weights/best.pt
```

如果没有找到，会递归搜索：

```text
trial_dir/train_runs/**/best.pt
```

找到后复制到：

```text
trial_dir/weights/best.pt
```

## mAP 解析

复用 `parse_yolo_metrics(text)`，兼容：

```text
Class     Images  Instances      Box(P          R      mAP50  mAP50-95)
all          100        200       0.91       0.88       0.93       0.71
```

```text
mAP50: 0.934
mAP50-95: 0.712
```

```text
metrics/mAP50(B): 0.934
metrics/mAP50-95(B): 0.712
```

`--metric map50` 使用 `map50` 作为 score。  
`--metric map50_95` 使用 `map50_95` 作为 score。

如果解析失败，请查看：

- `trial_xxx/val_stdout.log`
- `trial_xxx/val_stderr.log`

## Hybrid Proxy Score

只在 YOLO 类 evaluator 中有意义：

```bat
--hybrid-proxy-weight 0.2
```

分数计算：

```text
score = yolo_val_metric * 0.8 + proxy_score * 0.2
```

默认 `--hybrid-proxy-weight 0.0`，即只使用 mAP。

## 长图/大图裁剪预处理

对于 `8024×800` 这类极端长宽比图像，如果直接用 YOLO `imgsz=640` 训练，图像可能会被缩成大约 `640×64`，再 letterbox 到 `640×640`。目标在训练输入中会变得非常小，容易导致检测不到目标，表现为 `mAP50` 长时间为 0。

这类数据建议先做一次手动裁剪预处理，再把裁剪后的 YOLO 数据集交给 `train_yolo` 做自动增强策略搜索。裁剪预处理的目的：

- 保持目标在训练输入中足够大。
- 减少极端长宽比对 YOLO resize/letterbox 的影响。
- 同步转换 YOLO 标签，保证 bbox 仍然合法。
- 为后续 `train_yolo` 搜索提供更合理的数据集。

裁剪工具是独立 CLI：

```bat
python tools\tile_yolo_dataset.py ^
  --dataset E:\TJGY\DataSet\yolo-test ^
  --output E:\TJGY\DataSet\yolo-test-tiled ^
  --mode sliding_window ^
  --tile-width 1280 ^
  --tile-height 800 ^
  --overlap 200 ^
  --min-box-visibility 0.5 ^
  --keep-empty false
```

它不是随机增强策略，不会注册为 augmentation operation，也不会被 `SearchSpace` 或 `RandomSearch` 采样。流程顺序应该是：

1. 原始长图先裁剪成较小 YOLO 数据集。
2. 检查裁剪输出的图片和标签。
3. 使用裁剪后的数据集运行 `train_yolo`。

### sliding_window 模式

`sliding_window` 适合长条图。它按 `tile_width`、`tile_height` 和 `overlap` 生成滑动窗口，对每个窗口裁剪图片，并计算窗口和原始 bbox 的交集。保留 bbox 时会把坐标转换到 tile 内部，再保存为 YOLO 归一化格式。

推荐参数：

```text
tile_width=1280
tile_height=800
overlap=200
min_box_visibility=0.5
keep_empty=false
```

### object_aware 模式

`object_aware` 适合优先保护目标框。它以每个目标 bbox 的中心生成一个 `tile_width × tile_height` crop；如果目标靠近图像边缘，会自动移动 crop，保证 crop 不越界。同一个 crop 中可以包含多个目标，重复窗口会做简单去重。

示例：

```bat
python tools\tile_yolo_dataset.py ^
  --dataset E:\TJGY\DataSet\yolo-test ^
  --output E:\TJGY\DataSet\yolo-test-tiled-object ^
  --mode object_aware ^
  --tile-width 1280 ^
  --tile-height 800 ^
  --min-box-visibility 0.8 ^
  --keep-empty false
```

### bbox 保护规则

裁剪工具支持这些保护参数：

- `--min-box-visibility 0.5`：裁剪后 bbox 面积 / 原 bbox 面积。低于阈值的残缺框会被丢弃。
- `--min-box-area 4`：裁剪后 bbox 像素面积太小时丢弃。
- `--keep-empty false`：默认不保存没有目标的 tile；设为 `true` 时会保存空 txt。
- `--clip-boxes true`：默认将 bbox 裁剪到 tile 边界内；输出 YOLO 坐标会归一化到 `0~1`。

如果一个目标框被 tile 截掉太多，不会保留这个残缺框。由于重叠切片，同一个目标在多个 tile 中重复出现是允许的。

### 裁剪输出结构

```text
output_root/
  images/
    train/
    val/
  labels/
    train/
    val/
  tile_report.json
  tile_report.csv
  README.txt
```

`tile_report.json` 和 `tile_report.csv` 会记录原图路径、输出 tile 路径、tile 坐标、原始 bbox 数、保留 bbox 数、丢弃 bbox 数和是否为空 tile。

## 诊断驱动的数据增强

默认 `RandomSearch` 的局限是：它只是随机试增强组合，不理解模型为什么失败；如果每个 trial 都要训练 YOLO，盲目试策略的成本会比较高。诊断驱动增强不是强化学习，也不是深度学习策略生成器，而是一个启发式闭环：先看 baseline 模型在验证集上错在哪里，再把搜索空间往更可能有效的增强方向收缩和加权。

推荐流程：

1. 先训练一个 baseline，或者准备已有 `best.pt`。
2. 在固定 `val` 上运行错误分析：

```bat
python tools\analyze_yolo_val_errors.py ^
  --dataset E:\TJGY\DataSet\yolo-test-tiled ^
  --weights outputs\baseline_compare_tiled\baseline_no_aug\weights\best.pt ^
  --output outputs\diagnostics\baseline_error_analysis ^
  --imgsz 640 ^
  --conf 0.25 ^
  --iou 0.5
```

3. 工具会读取 `images/val`、`labels/val` 和 YOLO 预测结果，按 IoU 匹配 GT 与预测框，统计 TP、FP、FN、弱定位、小目标、边缘目标、低对比度区域等问题。
4. 输出：

```text
outputs/diagnostics/baseline_error_analysis/
  error_summary.json
  error_summary.csv
  per_image_errors.csv
  per_object_errors.csv
  diagnosis_report.txt
  augmentation_advice.json
  augmentation_advice.txt
  advisor_search_space.json
  visualizations/
```

5. 再把诊断生成的 search space 交给 `train_yolo`：

```bat
python examples\run_policy_search.py ^
  --dataset E:\TJGY\DataSet\yolo-test-tiled ^
  --output outputs\advisor_policy_search ^
  --trials 50 ^
  --samples 90 ^
  --seed 42 ^
  --evaluator train_yolo ^
  --metric map50_95 ^
  --model yolov8n.pt ^
  --epochs 10 ^
  --imgsz 640 ^
  --batch 4 ^
  --hybrid-proxy-weight 0 ^
  --search-space-json outputs\diagnostics\baseline_error_analysis\advisor_search_space.json
```

如果不传 `--search-space-json`，项目仍使用原来的默认随机搜索空间。传入后，搜索空间会使用 `allowed_operations`、`operation_weights`、`strength_ranges`、`prob_ranges` 和 `forbidden_combinations` 来加权采样和限制不合理组合。

诊断规则示例：

- 小目标漏检高：降低 blur/noise 权重和强度，增加 sharpen/CLAHE/scale/translate 权重，同时建议增加裁剪 overlap 或 object-aware crop。
- 边缘目标漏检高：增加 translate/scale/affine 权重，同时建议增加裁剪 overlap。
- 低对比度漏检高：增加 contrast/gamma/CLAHE/sharpen 权重。
- FP 多：建议 hard negative tiles、保留部分 empty tiles，并降低强噪声/强纹理增强。

当前限制：

- 诊断规则是启发式规则，不是强化学习或自动证明有效的策略优化器。
- 预测结果质量会影响诊断质量；baseline 太弱时，错误模式可能不稳定。
- 小数据集的类别、尺寸和位置统计可能有较大方差。
- 诊断建议只是缩小搜索空间，最终仍需要用 baseline 对照实验验证。

## 当前限制

- `train_yolo` 需要用户本机已安装 YOLO 命令行环境。
- 默认命令按 Ultralytics YOLO 风格组织，但可以用 `--train-command` 和 `--val-command` 替换。
- 模型文件如 `yolov8n.pt` 需要本机可访问，必要时 YOLO 会自行下载。
- mAP 解析依赖日志格式；解析失败时看 val 日志。
- 每个 trial 都训练模型，速度显著慢于 proxy。
- Random Search 仍是随机搜索，后续可接入进化搜索或贝叶斯优化。
